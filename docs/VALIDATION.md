# Validation and numerical differences

These checks validate a prepared release candidate. They do not constitute a
complete rerun of the paper. Checks used Python 3.11.13 on macOS arm64, CPU only,
with one PyTorch thread. Exact package versions are recorded in
[`environment-verified.json`](environment-verified.json).
Machine-readable check results are retained in
[`validation-records/`](validation-records/).

## Checks completed

- All Python files and notebook code cells compile. All ten notebooks pass
  notebook-schema validation and contain no execution counts or stored outputs.
- The executable syntax trees of the two solver/utility files and the two
  included baseline implementations match the supplied originals after comments
  and docstrings are excluded. This check covers the core equations; it does
  not imply identical experiment orchestration or random states.
- All six exported inference checkpoints retain tensor-identical network
  weights. Optimizer states were omitted from these exports. Converted channel
  tensors are equal to the original NumPy arrays; problem-instance and system
  parameter files were copied without changes. Artifact hashes are recorded in
  [`artifacts.json`](../configs/artifacts.json).
- The first five retained Miami channels were regenerated using DeepMIMO
  4.0.0b11 and the original local scene. The maximum absolute difference was
  zero. System parameters and the first five test instances also matched.
  This does not validate every receiver or a newly downloaded scenario revision.
- The inference smoke check completed on two test instances at depth two.
  Weighted sum rates were finite, evaluation repeated consistently, and phase
  and power constraints passed the numerical tolerances below.
- Scratch training and a two-to-three-layer warm start each completed one
  optimizer batch and validation using four instances, and saved a checkpoint.
  Both checkpoints contained finite network weights and optimizer/scheduler
  states. Repeating scratch training with the same seed produced the same
  validation split and all 44 saved network tensors matched exactly.
  These checks establish bounded execution and repeatability, not convergence.
- Every code cell of Fig00–Fig06 ran in order with the bounded settings below.
  AO-MO, matrix decomposition, and all configured unfolded depths were exercised.
- The command-line notebook runner was also checked through an actual Jupyter
  kernel using Fig04 with one instance and all six depths. It selected the
  calling interpreter and saved the executed copy outside the source tree.

## Evaluation mode

Fig02 and Fig04 previously left their networks in training mode, which activates
dropout. The release uses `.eval()` and gradient-free inference. The following
comparison used the same weights, seed 42, and first two test instances. It
isolates dropout-active versus evaluation-mode execution in the checked
environment; it does not reconstruct an earlier interactive session's RNG state.

| Depth | Test index | Dropout-active WSR | Evaluation WSR | Difference |
| --- | --- | --- | --- | --- |
| 2 | 0 | 20.320627 | 21.759670 | +1.439043 |
| 2 | 1 | 22.506811 | 22.539564 | +0.032753 |
| 4 | 0 | 25.554153 | 26.293089 | +0.738935 |
| 4 | 1 | 27.448299 | 25.719885 | -1.728415 |

WSR is in bit/s/Hz. Differences can have either sign. The manuscript reference
tables remain separate in [`reference_results/`](../reference_results/README.md).
They are not represented as output regenerated by the corrected evaluation code.

## Floating-point constraints and warnings

The original solver's strict power check compares the maximum power ratio to
exactly one. In the smoke check, float32 projection produced a largest ratio of
1.0000001192092896. The verification helper reports both that strict result and
a power check with relative tolerance 2e-6. This tolerance changes only the
validation verdict; the original hybrid-precoder normalization is retained.
Phase checks use tolerance 2e-6.

The retained core can emit PyTorch warnings when it copy-constructs a tensor from
another tensor. These appeared during successful checks; the core operations
were retained for numerical continuity.

## Limits of verification

- No full training, complete figure sweep, or statistical agreement with all
  published values was checked. The original checkpoint training history is
  incomplete; see [training provenance](TRAINING.md).
- Installation was checked against the existing recorded environment. A fresh
  environment installation, another operating system, and GPU execution were
  not tested.
- Scenario download selection and reuse of the seven local scenes were checked.
  A fresh network download was not performed.
- Runtime measurements retain the original boundaries and exclude GNN inference
  in Fig03 and Fig04. See [experiment notes](EXPERIMENTS.md).
